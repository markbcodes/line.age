# Theme instructions

Edit the files in this folder. That is the source of truth for how an agent should build this theme.

The user may request any kind of site and any visual direction. The prompt decides what is built and how it looks. These files decide how it is modeled, rendered, built, seeded, and packaged: VX, templates, Tailwind/Vite, WordPress chrome, seeding, and packaging.

Do not treat architecture rules as a reason to simplify, conventionalize, or visually restrain the requested concept. Do not apply a Shader house style. When the brief is short, infer a look from the domain; a short brief still gets a designed site. A named site is the look; do not replace it with a domain stereotype.

Read the files for the current phase:

1. Plan — `workflow.md`
2. Model — `vx.md`
3. Visible MVP — `templates.md`, `visual.md`, `performance.md`, `blocks.md`, and `build.md` together
4. Seed — `seeding.md` and `media.md` after the VX-wired templates exist
5. Expand — remaining routes in `workflow.md`, in the same turn, after seeded rendering is verified
6. Inspect — `quality.md` once, on the finished set

`AGENTS.md` at the theme root is a short always-on contract for any coding agent, `INDEX.md` is the theme's structure, generated by Shader, and `MAP.md` records decisions. If this folder disagrees with a leftover note elsewhere, follow this folder.
